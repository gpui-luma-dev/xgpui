GPUI 1.29.3 migration

Draft — not released. The GPUI sources follow gpui-unofficial 1.29.3 (Zed v1.29.3). Tracking issue: #406.

This page lists only the changes that can stop your code from compiling, with the fix for each. Behavior changes and new APIs are in What's new; the complete record is the API ledger.

Update the GPUI family together

xgpui takes a major version. Its types are distinct from the previous major's, so every crate whose public API exposes them takes a breaking version too. Move all of them in one step; mixing majors produces type-mismatch errors between, for example, an extension's elements and your gpui. The version table is added when the release is prepared.

Breaking changes and migration

ChangeCrateMigration
Every Element implements IntoElement through a blanket impl, and Element no longer requires IntoElement. A type with its own impl IntoElement next to impl Element fails with E0119 (conflicting implementations).xgpuiDelete the impl IntoElement block. IntoElement on components that aren't Elements, including #[derive(IntoElement)], is unchanged.
Along::apply_along takes impl Fn instead of impl FnOnce.xgpuiImplementors change FnOnce to Fn. Callers whose closure moves a captured value out clone it instead.
SharedString implements PartialEq by hand, so a const SharedString can no longer be used as a match pattern.xgpuiCompare with ==, or match on .as_ref() against string literals.
With feature bench-support: RandomizedElementTreeMutationKind and RandomizedElementTreeMutation gain a ChildText variant.xgpuiAdd a ChildText arm to exhaustive matches.

Removing a redundant IntoElement impl

impl Element for Gauge {
    // …unchanged…
}

// Delete this block: the blanket impl now provides it.
impl IntoElement for Gauge {
    type Element = Self;
    fn into_element(self) -> Self::Element {
        self
    }
}
