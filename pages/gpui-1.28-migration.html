GPUI 1.28.1 sync: changes and migration

Released on crates.io on November 15, 2026 from tag release-2026-11-15-04ba149f08ca. The GPUI sources follow gpui-unofficial 1.28.1 (Zed v1.28.1). Where an upstream change conflicted with XGPUI behavior, XGPUI's behavior was kept. Tracking issue: #284. Release notes on GitHub.

This page collects the details. The complete entry-by-entry record is in the API ledger and the upstream change accounting.

Update the GPUI family together

xgpui 4 types are distinct from 3.x types. Every crate whose public API exposes them took a breaking version: a major from 1.0, a minor before 1.0. Move all of them in one step, using the versions in the table below. xgpui-color and xgpui-macros are unchanged.

New APIs

  • Send-capable foreground executor: gpui::SendForegroundExecutor and ForegroundExecutor::to_send() let a worker thread submit a Send future that is polled on the main thread.
  • Anchoring: Anchored::attach(target, corner) places an element on a corner of a target and flips to the other side when that fits better.
  • Client corner radii: Window::set_client_corner_radii and PlatformWindow::set_client_corner_radii (default no-op) let apps that draw rounded corners tell the platform, so Wayland blur and input regions match.
  • Small helpers: Pixels::to_i32 (truncates, saturates, NaN is zero) and Keystroke::is_modifier_key.
  • macOS frame source: xgpui_apple::display_link::MetalFrameSource wraps CAMetalDisplayLink (macOS 14+, iOS 17+); MetalRenderer::set_frame_drawable and set_display_link_attached connect it to the renderer.
  • Web HTTP client: gpui_web::FetchHttpClient::new and with_user_agent are public and take a SendForegroundExecutor.
  • Benchmarks (feature bench-support): BenchWindowContext::simulate_resize, Window::rendered_scene, new RandomizedElementTree builders and a primitives benchmark.
  • Desktop shell: xgpui-shell 0.3.0 adds the window-control presenter (guide) and keeps the app-controlled title-bar colors from 0.2.0.

Behavior changes

  • macOS frame pacing: on macOS 14 and later, windows present through CAMetalDisplayLink, removing the roughly 33 ms nextDrawable stall that held animation at about 30 fps. Idle windows stop drawing. Earlier systems keep CVDisplayLink. Code that calls MetalRenderer::draw directly on an attached renderer must do so from the link's update.
  • Text: line breaks follow ICU/UAX #14 segments with grapheme awareness. Shaped clusters are never split and right-to-left runs wrap by segment, so line counts can change for CJK, RTL, hyphenated and punctuated text. CoreText keeps the first run's exact point size. DirectWrite draws tabs as invisible glyphs with their advance, so carets land on tab stops.
  • Frame limits: a frame pacer keeps throttled frames on a steady cadence. Redraws requested with cx.notify() stay unthrottled (see not adopted).
  • Cached views: reuse is invalidated when inherited opacity changes, and observers of entities read by reused cached content stay subscribed.
  • Wayland: each activation token carries its own request, so concurrent requests no longer overwrite each other (no stuck GNOME launch indicator). Blurred windows use ext-background-effect-v1, or KDE blur as a fallback. Blur and input regions follow client corner radii.
  • Windows: repeated synthetic mouse moves are dropped while real moves, drags and arrivals are delivered. A color-mode change requested during a draw is applied on the next frame instead of failing (#302). A shader program DirectX cannot compile is logged once and skipped instead of failing every frame (#303).
  • wgpu: the window surface is configured once at creation, removing 200–500 ms before the first frame on drivers with slow swapchain creation. Bounded device-loss recovery is unchanged.
  • Modifiers and keys: an unfinished standalone modifier sequence is flushed after the timeout, and macOS Spanish-ISO key equivalents are corrected.
  • Animations: with_animation uses the executor clock, so tests and benchmarks follow simulated time. Real-time behavior is unchanged.

Bug fixes

Fixes merged since the November 12 release, outside the upstream sync:

  • Windows pointer: leaving the window now sends MouseExited, so hover states and popovers clear; moving between the client area and the title bar doesn't count. The cursor set in WM_SETCURSOR is no longer overridden (#267, #70).
  • Windows maximize: Window::zoom_window restores a maximized window, matching its documented toggle on macOS and Linux (#278).
  • Windows drawing: the color-mode (#302) and shader-compile (#303) fixes listed under behavior changes.
  • Wayland diagnostics: frame-loop trace logging under xgpui::wayland::frame and a one-time warning when a frame callback is outstanding for over 500 ms, added while investigating the GNOME stall, which no longer reproduces (#276, #271).

The typography lab can also validate wide-gamut SDR presentation of glow and shadow effects (#282).

Not adopted from upstream

  • Notify-redraw throttling: upstream applies the low-power and inactive limits to cx.notify() redraws. That would cap engine surfaces at about 30 fps in unfocused windows and Low Power Mode, so XGPUI limits only animation-frame demand.
  • Web platform constructors: upstream stops attaching a Fetch HTTP client in gpui_platform::application() on Wasm. XGPUI keeps it, so cx.http_client(), URL images and requests keep working by default.
  • Inspector benchmark rewrite: it would drop XGPUI's render-count and child-validity checks.
  • Node test scripts for hello_web: XGPUI doesn't use Node.

Validation

  • Each backend's test suite runs in CI, with real-window checks: display-rate animation, no frames while idle and a live screenshot on macOS; synthetic mouse-move filtering on Windows; Wayland protocol checks under Weston and headless Mutter, and an X11 run under Xvfb.
  • All 22 macOS validation steps passed with zero warnings, including Wasm and iOS simulator compilation.
  • All 17 uploads were verified against crates.io checksums. A fresh project using only crates.io resolved all 19 exact versions, then built and ran on macOS.

Not covered: interactive iOS, physical-display gamut, compositor and screen-reader acceptance.

Known issues

  • The code example in the packaged xgpui-shell 0.3.0 README matches ShellControl without the fallback arm it needs outside the crate. The Desktop shell guide has the corrected example.
  • GNOME offers no background blur protocol, so Blurred windows are not blurred there.
  • The hello_web example remains unbuildable (upstream directory names in its paths) and needs nightly.
Source evidence and review hypotheses are kept distinct.
