GPUI 1.27.0 integration and API review

Integrated on codex/sync-gpui-1.27.0 from local commit 8ed97a3, using upstream f98d4e26ca850515c1682ae4cd6e2b8277dae6e7. Implementation is prepared for review; public API approval remains pending; the selected crate versions and exact pins are applied in this branch. No release or merge has been performed.

Breaking changes to XGPUI API

This migration changes the API exposed by XGPUI's core and Apple backend crates. Applications upgrading from the current XGPUI packages should review the changes below even if they do not use an optional extension. The table distinguishes upstream changes carried into XGPUI from adaptations to our GPUI interfaces.

XGPUI's own GPUI changes provide the core integration points used by our font, color, drawing, media and paragraph extensions. Those maintained differences, including earlier breaking changes to font and style structs, are described in GPUI API changes. The detailed review below records each API change in this sync, its origin, compatibility impact and application migration. Final API approval remains pending.

Upstream release reference

The upstream GPUI release tracker for 1.27.0 records the Zed GPUI changes from 1.26.2 to 1.27.0, with links to the original commits and pull requests. XGPUI's integration notes below describe how those changes are combined with our maintained GPUI modifications.

Implementation

  • Adopted typed upstream AppKit application, window, event, menu, keyboard, display, clipboard and appearance bindings; removed private native_appkit.
  • Retained XGPUI Metal resources, custom draw, wide SDR, media surfaces, caches, headless capture, and validation interfaces. Ported fallible device, library, pipeline, buffer, command queue and CoreVideo-cache initialization. Adopted validated atlas uploads while preserving our scoped texture ownership wrapper and eviction/lifetime regression tests.
  • Preserved local Services submenu registration, nullable pasteboard handling, Objective-C protocol/signature audits, optional text-range output handling, and attributed-string autorelease behavior. These fixes still apply to the upstream typed implementation.
  • Adopted power/platform introspection, host-aware key semantics, macOS atomic credential insertion, deferred native-close handling, list scroll anchoring, subscription activation changes, fallback caching and OHOS target exclusion.
  • Replaced window text locks with RefCell state and Rc ownership. Adapted our paragraph cache, retained-element reuse and generation invalidation; retained font axes/features/fallback controls and missing-glyph reporting.
  • Fixed scramble typography to re-shape its source font request when CoreText returns a size-specific face absent from reverse lookup. Replacements still require an exact native face match, preserving fallback and emoji behavior.
  • Supporting crates and provenance now reference 1.27.0. Existing XGPUI package versions follow the selected release table below. Final API review remains pending. macOS now requires 12.0; Metal shader compilation uses the same minimum.

The removed hash methods on the crate-private LineLayoutCache, private pasteboard UTType changes, and private subscriber-set changes are not downstream public APIs. Benchmark macros moved into a private module while retaining their exported names and availability. The shared Apple source mirror repeats core changes and is not a separate public API family.

XGPUI backend adaptations

The renderer factory drops its unused native window, view and bounds arguments, while MetalRenderer::new keeps XGPUI's existing two arguments and separate color negotiation. Both adopt upstream's fallible initialization. These changes adapt existing Apple backend entry points used to create platform windows; an extension cannot change their signatures or initialization error handling.

XGPUI's existing font, color, drawing, media and paragraph integration points are preserved. Their core-versus-extension design belongs in the maintained GPUI API changes guide. The upstream APIs in this migration retain their upstream role and are reviewed for compatibility.

Verification

All 16 suites in the macOS scripts/test_all.sh matrix passed across the full run and targeted reruns of release-sync, shader and labs after fixes. This includes the 426-test core suite, extension rendering tests, benchmark checks, native lab tests, CoreText tests, and iOS simulator test compilation.

Additional checks passed:

  • All shared Apple backend tests: 66 passed, one ignored GPU diagnostic.
  • macOS native backend tests: 16 passed, including protocol encoding audits, nullable pasteboard handling, optional text-range outputs and layer cleanup.
  • Native root cargo check --locked --offline --config .cargo/validation.toml.
  • Windows backend test compilation for x86_64-pc-windows-msvc, using the installed Homebrew LLVM resource compiler. This does not execute Windows tests.
  • Browser application compilation for wasm32-unknown-unknown, using the lab's extensions-web binary with feature web and its explicit single-threaded wgpu contract. The bare web crate without that application contract is not a supported single-threaded build configuration.
  • Selected-version audit: all 90 internal dependency requirements match the release map; all 200 selected-version entries across tracked lockfiles match.
  • Native workspace and every lab target compile with Apple/macOS 4.0.0.
  • The updated native consumer fixture compiles with explicit local overrides for the unpublished release family. Registry-only verification requires publication.
  • Release normalization, generated build-manifest consistency and all ten release-sync tests pass.
  • Regenerated documentation inventory and its JavaScript verifier.

Linux and OHOS native execution, browser interaction, iOS interactive execution, and physical-display color acceptance were not run in this macOS session. Existing ignored GPU diagnostics remain ignored; test success does not claim these additional platform acceptance results.
