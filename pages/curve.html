Curve and contour math. Geometry, plot curves, easing, mesh lattices, GPU field spines and node editing, with GPUI paths when you want them.

Curves

xgpui-curve is the curve and contour math for xgpui, also usable on its own. It covers segment geometry, arc length and path effects, plot series curves, tone curves and CSS easing, mesh-gradient lattices, curved field spines with matching WGSL and Metal shader code, an editable node path, squircles, variable-width strokes, freehand fitting and SVG path data. A gpui feature turns any of it into native GPUI paths.

Geometry uses xgpui-owned f64 types in xgpui_curve::geom. Kurbo provides numerical algorithms internally.

Use it

[dependencies]
xgpui-curve = "0.2.0"

Every module except geom has a feature of the same name (svg-path for svg_path), and all are on by default. Turn off default features and pick modules to use the math without GPUI:

xgpui-curve = { version = "0.2.0", default-features = false, features = ["series", "func"] }

Paint a curve in GPUI

Build any path in model space, map it into an element's bounds and paint it from a canvas. paint_contrasting_path draws a dark halo under a light line, so wireframes and gizmos stay readable on any background.

use gpui::{canvas, hsla};
use xgpui_curve::gpui_paint::{bounds_transform, paint_contrasting_path};
use xgpui_curve::geom::Point;
use xgpui_curve::series::{SeriesCurve, series_path};

// Samples in 0..1 of the element.
let samples = [Point::new(0.0, 0.8), Point::new(0.3, 0.2), Point::new(0.6, 0.6), Point::new(1.0, 0.1)];
let path = series_path(&samples, SeriesCurve::MonotoneX);

canvas(|_, _, _| (), move |bounds, _, window, _| {
    paint_contrasting_path(
        window,
        &path,
        bounds_transform(bounds),
        (4.0, hsla(0.0, 0.0, 0.0, 0.6)),
        (2.0, hsla(0.0, 0.0, 1.0, 0.9)),
    );
})

fill_path and stroke_path return the gpui::Path<Pixels> without painting it, for callers that want their own colours or layering.

Plot series and area fills

series_path connects samples in input order. A non-finite sample breaks the line and each finite run is drawn on its own. The curve family follows d3-shape; monotone curves use the same PCHIP slopes as scipy and the luma plot crate, so they never overshoot.

use xgpui_curve::geom::{Point, Rect};
use xgpui_curve::series::{Baseline, SeriesCurve, series_area, series_path_clipped};

let samples = [Point::new(0., 3.), Point::new(1., 5.), Point::new(f64::NAN, 0.), Point::new(3., 4.), Point::new(4., 6.)];
let line = series_path_clipped(&samples, SeriesCurve::CatmullRom { alpha: 0.5 }, Rect::new(0., 0., 4., 5.5));
let area = series_area(&samples, SeriesCurve::Natural, Baseline::Constant(0.));

series_path_closed draws one closed outline, such as a radar chart, with d3's closed curves (ClosedCurve::Linear, Basis, Cardinal and CatmullRom). The curve wraps from the last sample to the first with no corner at the seam. Here a non-finite sample is skipped rather than breaking the outline.

use xgpui_curve::geom::Point;
use xgpui_curve::series::{ClosedCurve, series_path_closed};

// One value per radar spoke, as points around the centre.
let values = [0.9, 0.55, 0.75, 0.3, 0.85];
let spokes: Vec<Point> = values.iter().enumerate().map(|(i, v)| {
    let angle = i as f64 * std::f64::consts::TAU / values.len() as f64;
    Point::new(v * angle.cos(), v * angle.sin())
}).collect();
let outline = series_path_closed(&spokes, ClosedCurve::CatmullRom { alpha: 0.5 });

Mesh-gradient lattices

A MeshLattice is an R × C grid of points with a tangent per node and axis: Tangent::Auto (central difference, one-sided at the border) or Tangent::Explicit. Both are clamped to 0.7 × the distance to the nearer neighbour, which keeps patches from folding. Its edges are the exact cubic boundaries of the mesh-gradient patches, so a wireframe drawn from the lattice lies on the rendered edges.

use xgpui_curve::geom::{Point, Vec2};
use xgpui_curve::mesh::MeshLattice;

let points = (0..3).flat_map(|r| (0..4).map(move |c| Point::new(c as f64 / 3., r as f64 / 2.))).collect();
let mut lattice = MeshLattice::new(3, 4, points)?;

// Grab a wire about a third of the way along and drag: the point follows the cursor exactly.
if let Some(hit) = lattice.hit_edge(Point::new(0.44, 0.51), 0.02) {
    lattice.drag_edge(hit.row, hit.col, hit.axis, hit.t, Vec2::new(0., 0.05))?;
}
let wires = lattice.wireframe();
let gpu_points = lattice.controls(); // positions and resolved tangents for xgpui_shader::MeshGrid

Dragging solves for the smallest change to the two inner controls that keeps the grabbed point under the cursor, then stores the result as explicit tangents at both nodes. A tangent is shared by the two edges on its axis, so the neighbouring edge bends too, and the fold clamp can stop a drag short. patch_point and iso_curve evaluate a cell's interior as the zero-twist Hermite patch the mesh shaders render, so iso-curves lie on the drawn gradient (they are exact cubics); reset_tangents returns every node to automatic.

Curved field spines

A CurveSpine is a quadratic Bézier a colour field can bend along. project returns, for any point, the nearest spine parameter t, the signed perpendicular distance and the normalized arc position s. Quadratics keep that projection in closed form (a cubic equation), so the GPU evaluates it per pixel.

use xgpui_curve::geom::Point;
use xgpui_curve::spine::CurveSpine;

let mut spine = CurveSpine::with_bend(Point::new(0.2, 0.5), Point::new(0.8, 0.5), 0.3);
// The seam rule: straighten until the projection is continuous out to 0.6
// (this bend's reach is 0.5).
spine.limit_bend(0.6);
let local = spine.project(Point::new(0.5, 0.4));
let arrow = spine.arrowhead(0.03, 0.45); // wings along the terminal tangent
let params = spine.shader_params(0.0, 1.0); // [p0, control, p1, t_min, t_max] as f32

The seam. Beyond the centre of curvature on the inside of a bend, the nearest point can jump between the arms. reach() is that distance (1 / maximum curvature); limit_bend(radius) straightens the spine until the reach is at least the radius your kernel samples.

Shaders. CURVE_SPINE_WGSL and CURVE_SPINE_MSL (include it after #include <metal_stdlib>) define curve_spine_project(p, p0, c, p1, t_min, t_max), returning (signed distance, t, s, length). Straight spines, coincident points and edge-of-domain inputs stay finite. Tests run both versions on Metal and compare them with the f64 CPU result. The curve lab's spine inspector has a CPU-vs-GPU difference view that does the same comparison live, tile by tile, and highlights any tile off by more than half a pixel.

let source = format!("{}\n{}", xgpui_curve::spine::CURVE_SPINE_WGSL, include_str!("my_field.wgsl"));
// In my_field.wgsl:
//   let r = curve_spine_project(input.position, p.a.xy, p.a.zw, p.b.xy, p.b.z, p.b.w);

Editable node paths

NodePath holds anchors with optional handles and a mode per node. Edits keep each mode's constraint: Smooth handles stay collinear, Symmetric ones also stay equal in length, and automatic nodes recompute their handles from the anchors.

use xgpui_curve::geom::{Point, Vec2};
use xgpui_curve::node::{AutoSmooth, Node, NodeMode, NodePath};

let anchors = [(110., 330.), (270., 180.), (450., 300.), (630., 170.)];
let mut path = NodePath::new(anchors.iter().map(|&(x, y)| Node::auto(Point::new(x, y), AutoSmooth::Hobby)).collect(), false)?;
path.drag_segment(1, 0.4, Vec2::new(0., -20.))?; // the point at t = 0.4 follows the cursor
let inserted = path.insert_at(2, 0.5)?;          // the drawn curve is unchanged
path.set_mode(inserted, NodeMode::Symmetric)?;
let comb = path.curvature_comb(24, 4000.);       // (point, tip) pairs to draw
ModeBehaviour
CornerC⁰: handles move independently
SmoothG¹: handles stay collinear and opposite, lengths independent
SymmetricCollinear, opposite and equal in length
Auto(CatmullRom { alpha })From the two neighbouring anchors; alpha 0.5 is centripetal
Auto(Natural)C² natural spline over each run of natural nodes
Auto(Hobby)Hobby's algorithm (unit tension, unit curl ends) over each run

Moving a handle of an automatic node turns it into a Smooth node. insert_at freezes the automatic nodes that depend on the split segment so the curve does not move.

Tone curves and easing

use xgpui_curve::func::{Easing, FunctionalCurve, StepPosition};
use xgpui_curve::geom::Point;

let tone = FunctionalCurve::monotone(&[Point::new(0., 0.), Point::new(0.5, 0.65), Point::new(1., 1.)])?;
let lut = tone.to_lut_f32::<256>(); // finite, clamped to 0..=1, for a GPU lookup
let y = Easing::EASE.eval(0.5);
let steps = Easing::steps(4, StepPosition::JumpEnd)?;
let overshoot = Easing::cubic_bezier(0.5, -0.5, 0.5, 1.5)?;

FunctionalCurve holds y = f(x) over strictly increasing knots, as PCHIP (no overshoot), linear, or Bézier segments whose handle x is clamped so every x has one y. Easing follows CSS Easing Level 2, including extrapolation outside 0..1 and linear() stops with missing inputs.

Shapes, strokes and freehand fitting

use xgpui_curve::fit::{FitOptions, fit_cubic_path};
use xgpui_curve::geom::{Point, Rect};
use xgpui_curve::shape::Squircle;
use xgpui_curve::stroke::{Cap, StrokeProfile};

let card = Squircle::new(Rect::new(0., 0., 240., 160.), 32., 0.6)?.to_path(0.05);
let pointer: Vec<Point> = (0..60).map(|i| Point::new(i as f64 * 5., (i as f64 * 0.2).sin() * 40.)).collect();
let fitted = fit_cubic_path(&pointer, FitOptions { tolerance: 2., ..Default::default() })?;
let ink = StrokeProfile::tapered(14., 0.25, 0.3)?.caps(Cap::Round).outline(&fitted, 0.25)?;

Squircle uses Figma's corner construction but splits the transition handles so curvature is continuous where the corner meets the circular arc: measured curvature steps stay below 1e-4 × 1/R. Short sides reduce the smoothing first, then the radius. ArcShape draws d3-style annular sectors with padding and analytic contains. StrokeProfile offsets each side by half the width at that arc length; constant-width strokes can use stroke_outline with StrokeStyle.

Arc length, trim, dash and SVG

use xgpui_curve::measure::{MeasuredPath, PathEffect};
use xgpui_curve::svg_path;

let path = svg_path::parse("M10 10 C40 80 90 -20 120 40 S200 60 220 10")?;
let measured = MeasuredPath::new(&path, 1e-6)?;
let halfway = measured.locate(measured.length() / 2.).map(|at| at.point);
let dashed = measured.apply(&PathEffect::new().trim(0.1..0.9)?.dash(&[8., 4.], 0.)?)?;
let d = svg_path::to_svg(&dashed);

Trim and dash keep the original curve segments; dashes restart on each subpath and join across the start of a closed one. Work is bounded (8192 segments, 16384 output pieces, 64 dash entries).

Precision and tests

  • Nearest point within 1e-6 of a brute-force search; quadratic arc length within 1e-12 of the analytic parabola and 1e-9 of quadrature; arc-length lookup within 1e-9.
  • Bounds checked against 100,000 samples; splits preserve geometry and derivatives.
  • Mesh and node segment drags keep the grabbed point under the cursor; insert_at leaves every sampled point in place for every node mode.
  • Automatic mesh tangents match the xgpui-luma gradient builder; PCHIP matches the luma plot implementation.
  • The spine WGSL and hand-written MSL run on Metal, with fast math off and on, and agree with the CPU.

Known limits

  • No path boolean operations (union, intersection, difference).
  • Spines are quadratic so the GPU projection has a closed form; cubic spines would need an iterative solve per pixel.
  • Hobby with unit curl overshoots on sharp zig-zags, as the algorithm does.
  • Intersections of overlapping (coincident) curves return a bounded sample of shared points.

GPUI public API changes: additions and compatibility

None. The crate uses existing PathBuilder, Window::paint_path and element APIs behind its optional gpui feature; everything else is plain Rust. See curve integration compatibility.
