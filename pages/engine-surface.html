Experimental GPU engine surfaces. Present frames from your own GPU engine into xgpui, with no copies.

GPU engine surfaces

EXPERIMENTAL — Not published; the API is under review.

xgpui-engine-surface lets a GPU engine you own present frames into an xgpui window, the way it would present to a swapchain. The engine keeps its own device, queue and thread, and can render or run compute shaders as it likes. xgpui composites the result like any other element: no copies, no extra synchronisation code in your app, and wide-gamut colour where the window supports it.

Use it when xgpui-shader paints are not enough: long compute passes, image pipelines, simulations or anything that should not run inside GPUI's frame.

Use it

For development against this checkout:

xgpui-engine-surface = { path = "path/to/extensions/crates/xgpui-engine-surface", features = ["wgpu"] }

Create the target on the engine's thread, render into an acquired slot and present it. Paint the surface from any element:

let mut target = WgpuSurfaceTarget::new(SurfaceDesc {
    width: 640,
    height: 400,
    format: SurfaceFormat::Rgba16FloatLinearP3, // or Bgra8Srgb
    slots: 3,
}, &device, &queue)?;

// Engine thread
let slot = target.surface().acquire()?;    // Err(WouldBlock) when the ring is full
let texture = target.texture(&slot)?;      // render or compute into it
target.present(slot, [encoder.finish()])?; // submits, then publishes the frame

// UI thread, in an element's paint phase
surface.paint(window, bounds, radii);

EngineSurface is cheap to clone, so hand a clone to the view and keep the target on the engine thread. On Linux, create the engine's device with WgpuSurfaceTarget::request_device so it can share memory with the compositor.

If the compositor cannot use the surface (for example, the engine is on a different GPU), the first frame fails with a typed Unsupported reason and EngineSurface::unsupported() reports it.

Colour

  • Bgra8Srgb shows the same in every window.
  • Rgba16FloatLinearP3 shows in wide gamut in a WideGamutSdr window and as a mapped sRGB preview elsewhere. paint picks per window; content and preview_content pick explicitly. RGBA16F slots accept storage writes, so compute shaders can write them directly.

Colour is checked against a CPU reference on all three platforms. See colour workflows for how wide-gamut windows work. Linux shows the sRGB preview until native wide gamut lands (#146).

What it guarantees

  • Published frames don't change. A slot is never rewritten while a window shows it, and returns to the ring once it no longer does. Use 3 slots plus one for each extra window showing the surface.
  • A misbehaving engine can't freeze the UI. Until a frame is ready, the last ready frame stays on screen. A GPU hang is the exception: the driver's timeout handles it.
  • Device loss is recoverable. Call EngineSurface::invalidate() when the engine loses its device and create a new surface. When the compositor's device is replaced, slots are re-imported.

Heavy engines

SurfaceStats reports frames composited, frames never shown and the latency from present to first composition. If the engine saturates the GPU, turn on heavy mode so the UI keeps its frame rate:

target.set_heavy(Some(HeavyEngine::default()));
loop {
    let chunks = target.suggested_chunks(); // split the frame into short submissions
    render_frame_in(chunks, &mut target)?;
    std::thread::sleep(target.pace());      // back off while the UI lags
}

With four 4K engines saturating an Intel Iris Xe, the UI went from 5–6 frames in 6 s to a median of 16.7 ms per frame. Linux also runs the engine queue at low priority; Windows can't lower it through wgpu.

Frame rate and unfocused windows

GPUI rate-limits animation frames, the frames requested with window.request_animation_frame() or on_next_frame:

  • Unfocused windows get about 30 fps by default (WindowOptions::inactive_frame_interval, 33.3 ms). A second window showing a surface is unfocused most of the time.
  • Low-power mode caps animation frames at 30 fps in every window, on macOS, Windows and Linux.
  • Thermal pressure (serious or critical, reported on macOS only) caps animation frames in the active window at 60 fps.

A redraw requested with cx.notify() alone is not rate-limited. So instead of requesting an animation frame every display frame, redraw when the engine presents. EngineSurface::on_present runs on the engine's thread, so forward it to the view:

let (tx, mut rx) = futures::channel::mpsc::unbounded::<()>();
surface.on_present(move || {
    tx.unbounded_send(()).ok();
});
cx.spawn(async move |this, cx| {
    while rx.next().await.is_some() {
        if this.update(cx, |_, cx| cx.notify()).is_err() {
            break; // the view is gone
        }
    }
})
.detach();

New engine frames then appear at the engine's own rate in any window, and the UI does no work between frames. To keep animation frames at full rate in an unfocused window, open it with inactive_frame_interval: None. Low-power mode still applies.

API reference

The crate is not published, so there is no docs.rs page yet; this is the reference. Every item is re-exported from the crate root. For full rustdoc, run cargo doc --open -p xgpui-engine-surface --features wgpu.

EngineSurface

A ring of shareable slots presented into xgpui. Cheap to clone; the engine side and the view each hold one.

MethodPurpose
acquire() -> Result<SurfaceSlot, AcquireError>A writable slot. Frees slots whose GPU sampling has finished before giving up with WouldBlock.
present(slot, SyncPoint) -> Result<()>Publish a written slot. Frames with a submitted signal are shown at once with a GPU-side wait; others once their signal is observed reached. Adapters call this for you.
paint(window, bounds, corner_radii)Paint the latest frame, scaled and clipped to a rounded rectangle; picks wide or preview colour for the window.
content() / preview_content()The latest frame as CustomContent for a wide-gamut window, or as an sRGB preview for any other window.
on_present(callback)Called after every present and when a waiting frame becomes ready. Typically wakes the UI.
stats() -> SurfaceStatsCounters for diagnostics and pacing.
invalidate() / is_valid()Mark the surface dead after engine device loss. The last frame keeps showing; create a new surface on a new device.
unsupported() -> Option<String>Why the compositor could not use the surface (for example, a different GPU). It then offers no frames.
desc() / transport()The surface's fixed description, and how frames reach the compositor (always Transport::ZeroCopy).

SurfaceSlot: an acquired slot. index() is stable for the surface's lifetime (useful as a cache key); desc() repeats the surface description; on macOS iosurface() exposes the slot's IOSurface for raw Metal engines. Dropping a slot without presenting returns it to the ring.

SurfaceDesc and SurfaceFormat

ItemMeaning
SurfaceDesc { width, height, format, slots }Fixed slot properties. slots is 2–8: use 3, plus one for each extra window showing the surface. validate() checks sizes and the 512 MiB per-surface budget.
SurfaceFormat::Bgra8SrgbBGRA8, straight alpha, sRGB-encoded. Looks the same in every window.
SurfaceFormat::Rgba16FloatLinearP3RGBA16F, premultiplied, linear Display P3. Wide gamut in a WideGamutSdr window (macOS, Windows), sRGB preview elsewhere and on Linux. Allows storage (compute) writes.
bytes_per_pixel(), supports_storage(), color_mode(wide)Format helpers.

WgpuSurfaceTarget (feature wgpu)

The adapter for wgpu engines on all three platforms. It creates the shared slots on the engine's device, hands out wgpu textures and presents with a signal the compositor can wait on.

MethodPurpose
new(desc, &device, &queue)Create the slot ring on the engine's device. Check required_features() when requesting the device.
request_device(&adapter) (Linux)Create a Vulkan device with the external-memory extensions and, where supported, a low-priority queue (engine_queue_low_priority()).
surface() -> &EngineSurfaceThe surface to clone into the view.
texture(&slot) -> wgpu::Texture, format()The slot as a wgpu texture to render or compute into.
present(slot, command_buffers)Submit the frame's work with the slot's signal, then publish it.
set_gpu_wait(bool), gpu_wait(), gpu_sync()Turn off GPU-side waits (observe-only: frames show once complete).
set_heavy(Option<HeavyEngine>), heavy()Heavy-engine mode, and its current status.
pace() -> Duration, suggested_chunks() -> u32How long to wait before the next frame, and how many submissions to split it into, while the UI lags.

SyncPoint

The signal a presented frame waits on. With WgpuSurfaceTarget you never build one. On macOS, raw Metal engines use SyncPoint::new(event, value) (shown once reached) or the unsafe SyncPoint::submitted(event, value) (GPU-side wait; the signal must already be committed). On Linux and Windows, SyncPoint::completed() marks work that is already finished.

Stats, heavy mode and errors

ItemMeaning
SurfaceStatsSlots free / writing / published; totals presents, would_block, composited, unshown; waiting frames; composite_latency_ms from present to first composition.
HeavyEngine { max_hz, min_hz, lag_budget_ms, chunk_ms, max_chunks }Defaults 60 Hz, 0.25 Hz, 33 ms, 4 ms, 64. Pace down when compositor latency exceeds the budget; split frames into submissions of about chunk_ms.
HeavyStatus { config, rate_hz, frame_ms, suggested_chunks }What heavy mode is currently doing.
AcquireError::WouldBlockEvery slot is in use; retry after the next presented frame.
AcquireError::InvalidatedThe surface was invalidated; create a new one.
Unsupported(String)The platform or configuration cannot support a surface.

Try it

Run from the repository root:

cargo run -p xgpui-ext-lab --bin gpu-canvas-workbench
cargo run -p xgpui-ext-lab --bin engine-surface-lab -- --threaded

The GPU Canvas Workbench is a small editor on a compute engine: edits are checked against a CPU reference, with a second window, minimize, resize, pan/zoom, wide versus sRGB comparison (--compare) and simulated device loss. --check runs it as an automated test. The engine surface lab stresses surfaces: --stress-surfaces N --stress-size WxH --work N [--heavy].

Run the tests with:

cargo test -p xgpui-engine-surface --all-features

Tested on Apple M-series, Intel Iris Xe (Fedora 44 and Windows 11) and Intel Arc 140T (Windows 11). Evidence per machine is in #198; the design is in #197, and open follow-ups are in #227.

GPUI public API changes: additions and compatibility

Seven additive hooks in gpui-wgpu, gpui-windows and gpui-apple let the extension adopt shared textures and wait on engine signals. Nothing in gpui itself changes and no application needs to migrate. See engine surface API changes.
