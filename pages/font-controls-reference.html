Font controls reference

Issue: https://github.com/gpui-luma-dev/xgpui/issues/27

The web font-controls guide covers usage, support and core 3.0 migration. This page holds the implementation contract, measurements and individual API rationale.

Feature introspection

Resolve a font, then query the resolved face:

let id = text_system.resolve_font(&gpui::font("Inter"));
match text_system.opentype_features(id)? {
    gpui::FontQuery::Unsupported => { /* Hide the feature inspector. */ }
    gpui::FontQuery::Supported(features) => {
        // An empty list is a successful query with no GSUB/GPOS features.
        for feature in features {
            println!("{}: GSUB={} GPOS={}",
                feature.tag, feature.substitution, feature.positioning);
        }
    }
}

The result is a sorted union of the face's GSUB and GPOS FeatureLists. It records table provenance, merges duplicate tags, and returns errors for unreadable feature metadata or invalid font IDs on supporting backends. The reader validates feature records, not the complete shaping tables. It does not enumerate AAT features, named stylistic-set labels, allowed values, or script/language associations. Feature presence does not establish that a feature applies to a particular script, language, text, or variation instance. It describes this face only; fallback runs can use other faces. As with other font queries, font IDs belong to the text system that created them.

Apple's font-kit backend, Parley, and DirectWrite implement feature and axis queries. DirectWrite static axes require the runtime IDWriteTextLayout4 probe to succeed. Native/Parley font-controls labs and tests are verified on macOS and Windows. Parley in Wasm supports the same queries and static axes, exposed in the Wasm inspector. Cosmic now implements table access for resolved font files, including collection faces, and reports feature/axis inspection support. Its arbitrary static axis requests remain rejected. The default Cosmic/Canvas web wrapper still reports inspection as Unsupported; it does not expose the new native Cosmic hook. TextSystem::font_capabilities() reports support explicitly. Unsupported backends reject nonempty axis requests in their font_id entry point rather than silently pretending to apply them. Note that GPUI's existing resolve_font convenience method can fall back on resolution errors; callers should check capabilities before presenting axis controls. Err, Unsupported, and Supported(vec![]) must remain distinct in inspectors.

Use existing FontFeatures to request settings. Values are numeric OpenType parameters, not exclusively booleans. For example, ("cv02", 2) must retain 2; 0 disables a feature, while nonzero values can select different alternates. Enumeration does not change the descriptor or enable any features. Backend-specific shaping limitations still apply.

Precise variation values

FontTag accepts exactly four printable ASCII bytes, including spaces. Use FontTag::{WEIGHT, WIDTH, SLANT, OPTICAL_SIZE, ITALIC} for the registered axes. Constants avoid parsing in normal application code. Custom tags still use validated FromStr, and serialized tag strings are unchanged.

FontVariations::new accepts (FontTag, f32) pairs in font design units:

  • Coordinates remain signed and precise to f32; negative slant is preserved.
  • Reject NaN and infinities, even when a later duplicate would overwrite them.
  • Normalize negative zero to positive zero for consistent equality and hashing.
  • Sort tags and retain the last occurrence of each duplicate.
  • Do not quantize author values or clamp before the actual face is known.
  • Empty settings preserve existing font behavior.

Font::variations now carries these values through Apple, Parley, and the DirectWrite implementation. For normal element styling, use Styled::font_variations(...) or Styled::font(...); TextStyle::font_variations propagates them into text runs. Values serialize as a JSON map, such as {"slnt": -10.125, "wght": 500.25}. Deserialization validates every entry before canonicalizing duplicates.

let mut font = gpui::font("Roboto Flex");
font.variations = gpui::FontVariations::new([
    (gpui::FontTag::SLANT, -10.125),
    (gpui::FontTag::WEIGHT, 500.25),
])?;

Static-axis resolution rules

Apple, Parley, and the DirectWrite implementation use the following rules in shaping, metrics, glyph bounds, caret/selection geometry, fallback, and rasterization:

  1. Use existing family, weight, and style selection to choose the face. Explicit axes do not select another family or substitute for static-face matching.
  2. On that face, apply explicit coordinates after implicit weight/style axis settings. Explicit wght, ital, and slnt override the corresponding implicit coordinate. Other implicit coordinates remain as before.
  3. Clamp each supported axis to that resolved face's advertised minimum and maximum. Unsupported tags are ignored for that face; they do not fail font selection. Preserve the original author settings separately from effective coordinates so fallback faces can apply their own support and ranges.
  4. Apply this process independently to every fallback face. Do not transfer normalized coordinates between different faces. Resolved instance identity must describe the coordinates actually used throughout the pipeline.
  5. Explicit opsz is in font design units and follows the same rules. There is no new automatic optical sizing. Preserve existing backend defaults when opsz is omitted. Automatic sizing requires a later size-dependent identity design, including units, precedence, clamping, and fonts without opsz.
  6. Keep precise author coordinates distinct from any future preview policy. Preview quantization must occur before resolution and affect shaping and rendering together. The optional extension preview policy is described below; global budgets and frame-safe eviction remain separate.

Apple keeps requested descriptors separate from resolved native identity, then applies author coordinates to resolved fallback runs before reshaping. Its cascade now uses actual descriptors for in-memory user fallback fonts, which family-only cascade descriptors could not reliably resolve. Parley passes explicit variations through its shared flat-line/paragraph style builder and retains the resulting normalized coordinates in its existing face registry. Retained IDs are never recycled. Layout and raster keys continue to use FontId; no duplicate axis arrays were added to glyph or layout cache keys.

DirectWrite first resolves the native faces using normal selection/fallback. For each variable run, it clamps explicit coordinates against that face's font resource, creates an instance collection, and applies effective coordinates to an IDWriteTextLayout4 range. The final callback retains the actual shaped face for metrics/rasterization instead of selecting another face by family name. Numeric typography settings remain associated with the requested descriptor. In-memory user fallbacks use a collection containing custom and system fonts; owned font buffers remain alive for the text-system lifetime. Static faces ignore unsupported axes. The implementation and its five fixture tests have been cross-checked for MSVC but not executed on Windows yet.

Preview policy and measured baseline

The extension-owned xgpui_parley::VariationPreview accepts a fixed base font, per-axis ranges and intervals, and an explicit maximum number of admitted preview descriptors. It snaps coordinates before font resolution. Once the limit is reached, old settings still work and new settings return an error; the caller can keep displaying its last successful preview. Author coordinates remain precise and must be committed separately after editing. Keep the same controller for the inspector's lifetime. This controller does not evict IDs or atlas tiles and does not claim a global CPU/GPU memory bound.

A debug CPU diagnostic on this macOS/Apple Silicon host ran an 8 × 8 × 4 wght/wdth/slnt sweep three times, using the pinned Roboto Flex font, Hamburgefonts 012345, 28px, scale 1, and one subpixel variant. Migration for exhaustive literals

Prefer gpui::font(family) or Font { ... , ..Default::default() }. Existing exhaustive font literals need variations: Default::default(). Existing exhaustive text-style literals need font_variations: Default::default(); refinement literals need font_variations: None. Exhaustive patterns can name the new fields or use ... Empty coordinates preserve existing axis behavior. The in-memory Apple fallback correction described above is a separate behavior fix: requested embedded fallbacks can now resolve to their actual font.

Released scope and follow-ups

The release includes Apple, DirectWrite and Parley static axes, inspection, and measured previews. macOS and Windows labs and unit tests are confirmed working. The public API is reviewed and raw parsers remain private in core. Follow-ups:

  • #139: measured CPU/GPU budgets and frame-safe eviction
  • #140: DirectWrite static-axis and inspection parity
  • #141: Cosmic/Linux and web static-axis and inspection parity

Those follow-ups retain these gates:

  • Extend the baselines to all CPU caches, real frame times, multiple sizes, scale/subpixel variants, and drag-completion behavior. The current Metal diagnostic measures isolated atlas allocations, not rendered frames.
  • Design budgets and frame-safe invalidation/eviction. Cached scenes retain atlas tiles directly; removing glyph keys alone cannot guarantee cached views repaint or protect in-flight texture use. Font IDs must remain valid for old layouts. Existing removal hooks are not a complete policy.
  • Windows lab and unit-test acceptance is confirmed. #140 retains broader DirectWrite compatibility/host validation; the five standalone backend fixture tests are implemented and cross-checked for MSVC.
  • Cosmic inspection and Linux headless font validation are complete. #141 retains arbitrary-axis integration, interactive Linux desktop acceptance and default web backend parity; the bundled Cosmic interface does not expose arbitrary axis inputs. The Parley Wasm inspector already supports inspection and axes.
  • Automatic optical sizing remains explicitly deferred until size-dependent instance identity and coordinate mapping are specified and tested.

Do not advertise globally bounded scrubbing based on these isolated diagnostics. Later stages are tracked in the linked issues.

Ergonomics follow-ups

The standard axis constants are implemented. The following are design follow-ups, not callable APIs in this release:

  • Axis lookup and immutable editing helpers: a get operation, a validated with update, and without removal would avoid reconstructing settings for every control change. Removal must restore the backend/default axis behavior rather than writing an arbitrary zero. Equality, hashing and finite-value validation must keep their current guarantees.
  • Typed feature construction: FontFeatures currently exposes string/number pairs through an Arc<Vec<_>>. A typed constructor could accept validated tags while preserving numeric selectors, existing serialized input and compatibility.
  • Fallible resolution: a public error-returning resolver would let inspectors distinguish a missing/rejected requested font from successful fallback. The existing resolve_font intentionally falls back and can panic if the fallback stack also fails; it must retain that behavior for existing callers.

Each additional core API requires its own compatibility and ownership review.

Cosmic inspection milestone

CosmicTextSystem implements the existing PlatformTextSystem::font_table hook using the selected font's bytes and collection index. ttf-parser::RawFace reads the directory and table extent; the core's existing private parsers interpret GSUB/GPOS and fvar. Advertised unreadable tables return errors; absent tables return Supported(None). Invalid IDs return errors without indexing panics. No new core public type, field or method is introduced.

The backend reports feature and axis inspection, while static_variations stays false. The text lab displays inspection independently from axis editing. Tests cover pinned static/variable fonts, a two-face collection, invalid IDs, missing and corrupt table reads, and continued rejection of explicit axes.

Cosmic 0.19 still lacks a general arbitrary-axis shaping input in its attribute contract. Static-axis support remains a separate change spanning shaping, resolved-instance identity, fallback, metrics and Swash rasterization; painting with varied coordinates alone would be incorrect. Linux CI also runs the Parley library, native-host construction/axis smoke test and shared slider tests. Interactive Wayland/X11 and Linux IME/accessibility acceptance remain separate.

Validation at commit 8359fe8 passed on Ubuntu: 29 Cosmic tests, 36 active Parley library tests, the native-host construction/axis smoke test and shared slider tests. The complete validation run also passed native macOS/Windows, experimental iOS simulator and Wasm checks. The Linux host build exposed a stale DMA-BUF completion-guard call; the private guard now retains either staging allocations or imported textures, preserving resource lifetime and admission-release order. This adds no public API and is included in xgpui-wgpu 2.1.0; no additional version increment is needed for this fix within the same release.

Native and Parley comparison

On macOS or Windows:

just text --backend both

Two windows compare native CoreText/DirectWrite with Parley. Each has independent weight, width, slant and optical-size sliders. Use the same presets to compare matching settings. Drag a track or focus a slider and use arrows, Shift for larger steps, Home and End. Confirm both specimen sizes, wrapping and measured advance update together, without clipping. Default restores the original values.

The inspector uses steps of 10/1/0.25/1 design units and admits 512 combinations per window. When full, it holds the last preview and displays an explanation. Previously admitted settings and Default remain usable. Restart for a fresh session. This is not a global CPU/GPU memory budget or an eviction policy.
