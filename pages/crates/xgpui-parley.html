Why Parley

Stock GPUI shapes text with a different engine on each target: CoreText on macOS, DirectWrite on Windows, and cosmic-text on Linux and in the browser. Results differ from one to the next, and the gaps show up first in right-to-left and mixed text. Single-line Hebrew or Arabic labels work, but wrapped right-to-left text lays its lines out in painting order, so the first words land on the last line.

xgpui-parley plugs Parley and HarfRust in as GPUI's text system. Shaping, fallback, variable-font axes and paragraph layout are then the same on every platform and in Wasm, and with one call ordinary GPUI text (div().child(…), StyledText, tooltips, list rows, third-party widgets) handles wrapped right-to-left and mixed paragraphs. GPUI keeps its input handling, caches and glyph atlas.

Example: wrapped Hebrew in plain GPUI text

Two calls at startup. After that, ordinary text elements wrap right-to-left correctly; nothing in the UI code changes. Font registration is omitted; the right-to-left how-to has the complete app (just rtl-example):

use std::sync::Arc;
use xgpui_parley::{ParleyTextSystem, install_text_layout, typeset};

// 1. Parley as the text system, with your registered fonts.
let parley = Arc::new(ParleyTextSystem::new(fonts, "IBM Plex Sans")?);
let platform = gpui_platform::current_platform(false);
Application::with_platform_and_text_system(platform, parley.clone()).run(move |cx| {
    // 2. Lay out ordinary GPUI text with Parley.
    install_text_layout(parley.clone(), cx);
    // ... open windows as usual
});

// Anywhere in the UI: plain text now wraps right-to-left correctly,
// with each paragraph's direction taken from its own text.
div().w(px(260.)).child("טקסט עברי ארוך עובר לשורה הבאה, והמילים הראשונות נשארות בשורה העליונה מימין.")

// When the text can't decide (Latin first in a right-to-left UI), say so:
typeset("Release notes: גרסה 4.2 זמינה עכשיו").rtl()

With a native text system, that first div would show its first words on the bottom line. For explicit direction, line clamps, truncation and carets in right-to-left text, use typeset() or the paragraph API.

Public surface at a glance

ParleyTextSystem, retained face/variation identity and optional GPUI paragraph shaping/geometry. GPUI owns frame caches and the glyph atlas. Explicit static axes and VariationPreview share canonical GPUI descriptors.
