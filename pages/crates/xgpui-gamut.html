Why wide gamut

Most Macs and many recent laptops and monitors show Display P3, a noticeably larger range of colour than sRGB, especially in reds, oranges and greens. Stock GPUI draws standard 8-bit sRGB colour, so on those displays it cannot show the richer colours, however you write them: a photo's saturated reds and a brand colour defined in P3 come out flattened.

xgpui-gamut lets a window ask for wide-gamut SDR output and draw explicit linear-P3 content into it. The important part is what it does not change: existing sRGB paints, text and controls keep exactly their colours, converted by the compositor, so turning wide output on does not oversaturate the rest of the UI. The window reports what it actually got, because asking is not the same as the display presenting it. It is native on macOS (Metal) and Windows (D3D11); Linux wide output is deferred.

Example: a P3 red next to ordinary controls

The window opts in once; only content you mark as linear P3 uses the wider range:

use gpui::{WindowColorMode, prelude::*, px};
use std::sync::Arc;
use xgpui_gamut::WideColor;
use xgpui_shader::painted;

// Ask for wide-gamut SDR outside drawing, for example while opening the window.
let status = window.set_color_mode(WindowColorMode::WideGamutSdr)?;
let wide = status.effective() == WindowColorMode::WideGamutSdr; // asking is not getting

// Display P3's red lies outside sRGB: on a P3 display it is visibly richer.
let p3_red = Arc::new(WideColor::linear_p3([1., 0., 0., 1.])?);

painted()
    .w(px(320.))
    .h(px(200.))
    .bg_paint(p3_red)
    .child("Ordinary controls keep their sRGB colours")

Getting the P3 values right in the first place is colour science: converting from the source space, mapping colours P3 cannot show, blending in linear light. That is xgpui-color. See wide-gamut windows for the request, status and backend contract, and just gamut for the native comparison.

Public surface at a glance

WideColor::linear_p3 supports CustomContent; optional instanced WidePainter/WideGradient use explicit P3 shaders. Shared color math lives in xgpui-color; GPUI backends own presentation. Native color-lab compares P3 and mapped sRGB reference swatches with effective window/display status.
