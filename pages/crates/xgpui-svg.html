Why SVG

Stock GPUI's svg() element is built for icons: it draws the SVG as a single-colour mask, tinted with the text colour. That is ideal for a toolbar, but it cannot show an illustration, a diagram, a logo with its own colours, or a map you want to zoom into, and it rasterizes the whole image during paint, on the UI thread.

xgpui-svg renders full-colour documents, with gradients, filters and text, as an element you size, zoom and pan. Work is progressive: a coarse preview appears first and settles into sharp detail, rendered off the UI thread on desktop, and a shared scheduler keeps the image memory of many SVG views within a budget.

Example: a zoomable illustration

Parse once, keep the document in your view, and build the element during render. With stock GPUI this artwork would be one flat colour:

use gpui::{App, Context, Window, prelude::*, px};
use xgpui_svg::{SvgDocument, SvgScheduler, svg_image};

struct Artwork {
    document: SvgDocument,   // parsed once, kept in the view
    scheduler: SvgScheduler, // shared by every SVG view, with a memory budget
    zoom: f32,
}

impl Artwork {
    fn load(bytes: &[u8], cx: &App) -> anyhow::Result<Self> {
        let document = SvgDocument::parse(&cx.svg_renderer(), bytes)?;
        Ok(Self { document, scheduler: SvgScheduler::default(), zoom: 1. })
    }
}

impl Render for Artwork {
    fn render(&mut self, _: &mut Window, _: &mut Context<Self>) -> impl IntoElement {
        // Full colour, gradients and filters: a coarse preview first,
        // then sharp detail at the current zoom.
        svg_image("artwork", self.document.clone())
            .scheduler(self.scheduler.clone())
            .w(px(640.))
            .h(px(480.))
            .zoom(self.zoom)
    }
}

Keep using stock svg() for monochrome icons. See the SVG guide for scheduling, viewports and limits.

Public surface at a glance

SvgDocument, SvgImage/svg_image, RasterPolicy and SvgScheduler. Stable IDs retain progressive jobs; shared pools cap admitted jobs and accounted image costs. path_effects (trim and dash on Bézier contours) is deprecated in favour of xgpui-curve's measure module, which it now delegates to.
