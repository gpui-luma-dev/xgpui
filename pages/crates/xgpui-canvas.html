Why a spatial canvas

GPUI lays out the elements you give it, and a scroll container moves them. That is the right model for documents and lists, but not for a whiteboard, a node graph, a map or a design canvas. There is no zoom, positions are f32 pixels (so a large world loses precision far from the origin), and building an element for each of 100,000 items every frame is far too slow. Hit testing, rubber-band selection and snapping are left to you.

xgpui-canvas supplies the spatial layer underneath: an f64 camera with pan and pointer-anchored zoom, a retained scene with a bounding-volume hierarchy that returns only what is on screen with a suggested level of detail, hit testing and rectangle queries, alignment snapping, a density minimap, and (with the gpui feature) a clipped viewport with a procedural grid. You still draw ordinary GPUI elements, just far fewer of them. It is beta, and the API is expected to change.

Example: 100,000 cards, only the visible ones built

The camera math is plain Rust, so this runs without GPUI:

use xgpui_canvas::{Camera2D, LevelOfDetail, Point, Scene, SceneItem, WorldBounds};

// 100,000 cards over a large world, indexed once.
let scene = Scene::new((0..100_000).map(|i| {
    let (x, y) = ((i % 400) as f64 * 300., (i / 400) as f64 * 200.);
    let bounds = WorldBounds { min: Point { x, y }, max: Point { x: x + 240., y: y + 140. } };
    SceneItem { bounds, data: i }
}));
let mut camera = Camera2D::default();
let viewport = Point { x: 1200., y: 800. };

// Wheel or pinch at the pointer zooms around it; a drag pans.
camera.zoom_at(Point { x: 600., y: 400. }, viewport, 1.25);
camera.pan_by(Point { x: -40., y: 10. });

// Each frame, build GPUI children only for what is on screen.
for visible in scene.visible(camera, viewport) {
    match visible.detail {
        LevelOfDetail::Full => { /* a real card element at visible.screen_bounds */ }
        _ => { /* far away: a cheap proxy, no text or layout */ }
    }
}

// Clicks map back to the world, and hit the topmost card.
let clicked = scene.hit_test(camera.screen_to_world(Point { x: 610., y: 390. }, viewport));
