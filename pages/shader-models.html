Shader paints and instanced shaders

Both rendering models are experimental and require portable-shaders. Choose by integration and workload; neither name implies stabilization or broader backend support.

Backend implementation does not establish driver acceptance on every platform. The shader-paint guide and instanced shader guide record runtime validation and remaining platform checks. Main-pass batching preserves draw order; it does not sort all matching programs together. Reuse compiled programs in either model.

Migration from v1/v2 terminology

“v1” referred to shader paints; “v2” referred to instanced shaders. These are parallel rendering models, not successive releases of one API. Existing guide filenames remain available to preserve incoming links.

// Before: removed beta API.
use xgpui_shader::experimental::{ShaderParameters, ShaderProgram};
let program = ShaderProgram::new_v1(source)?;

// After: identical source and output contracts.
use xgpui_shader::shader_paint::{ShaderParameters, ShaderProgram};
let program = ShaderProgram::new(source)?;
let paint = program.paint(ShaderParameters::new().float("gain", 0.5))?;

ShaderPaint is also exported from shader_paint. The old experimental module and new_v1 constructor have been removed as a breaking beta API change; update all callers to the new names. No aliases or deprecated forwarding APIs remain. instanced::ShaderProgram<T>::new and typed instance terminology are unchanged.

Version numbers are reserved for actual source-contract or ABI revisions within each rendering model. Naming changes do not relax validation, change color semantics, or add backend support.
