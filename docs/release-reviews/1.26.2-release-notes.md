# XGPUI release proposal: GPUI 1.26.2

**Proposed release; versions and publication await review.**

This release updates the framework to [gpui-unofficial 1.26.2](https://github.com/gpui-archipelago/gpui-unofficial/tree/release/1.26.2/crates), captured from Zed `c4273271092b0287f7d181f616bd5171e0a2f70c`. It also includes XGPUI changes merged since the last completed release, [release-2026-10-31-ed4469267251](https://github.com/gpui-luma-dev/xgpui/releases/tag/release-2026-10-31-ed4469267251).

Comparison baseline: `ed4469267251f68fcc9c96c2957ece8912084630`. Integration source: `eda9c2589abe94b5c48ab0087b2e6d2979ec4fea`. The upstream version identifies provenance; downstream crate versions are chosen independently.

## Highlights

- **GPUI 1.26.2 integration.** Adds optional debug hot reload, application lifecycle and memory-warning callbacks, native text-selection/content notifications, back gestures, touch-scroll improvements, focus cleanup and sprite batching fixes. The matching supporting packages remain registry dependencies pinned to `=1.26.2`. ([#123](https://github.com/gpui-luma-dev/xgpui/pull/123))
- **objc2 remains the Apple foundation.** The existing objc2/objc2-metal conversion is retained. macOS fixes cover native argument signatures, nullable pasteboards, Services-menu behavior, and nullable open/save panels. These are follow-ups to the earlier migration. ([#105](https://github.com/gpui-luma-dev/xgpui/pull/105), [#106](https://github.com/gpui-luma-dev/xgpui/pull/106))
- **Bounded Metal producer recording.** Native producers use a host-owned preparation batch through `MetalCustomContext::record`. Queue identity remains available for caching, while direct producer access to the host queue is removed. This bounds unsubmitted command buffers as producer count grows. ([#121](https://github.com/gpui-luma-dev/xgpui/pull/121))
- **Retained raster viewports and GPU adjustments.** Media adds bounded `RasterSource` input, `CanvasPaint`, sampling-only adjustments and presentation of the previous overview while a replacement uploads. Admission retry handles retiring workers without leaking reservations. Storage, decode and upload budgets remain explicit. ([#121](https://github.com/gpui-luma-dev/xgpui/pull/121))
- **Display P3 window option.** The new `use_display_p3` option negotiates the existing macOS wide-gamut SDR compositor, preserving sRGB UI color interpretation and objc2 ownership. Unsupported requests retain default presentation. This does not add HDR. ([#123](https://github.com/gpui-luma-dev/xgpui/pull/123))
- **Upstream-derived iOS backend.** Proposes the first `xgpui-ios 1.26.2` publication from `gpui/crates/gpui-ios`. UIKit lifecycle, windows, touch, keyboard, safe-area/keyboard insets and native text input use objc2 and the shared XGPUI Apple renderer. Compile/link/package checks pass; interactive simulator/device acceptance is pending. Wide-gamut SDR presentation remains macOS-only. ([#123](https://github.com/gpui-luma-dev/xgpui/pull/123))
- **Working benchmark support.** Bundles the omitted Zed benchmark metrics source behind `bench-support`, restores platform benchmark compilation, and adds cross-platform metrics/context checks. The profiler was already present; the restored measurement support adds allocation, resource and hardware counters where available. ([#123](https://github.com/gpui-luma-dev/xgpui/pull/123))

## Migration notes

1. **Update the GPUI family together.** `xgpui 2.0.0` types are distinct from 1.x types. Use platform/backend versions from the table and matching extension versions. Pure `xgpui-color 0.3.0` remains compatible and unchanged.
2. **Scroll events.** Replace `PlatformInput::ScrollWheel(event)` with `PlatformInput::Scroll(event)` and review matches for the new `BackGesture` variant. Prefer `ScrollEvent`, `ScrollSource` and `on_scroll`. The old `ScrollWheelEvent` alias and `on_scroll_wheel` methods remain deprecated compatibility names, but complete event literals must supply the new `source` field.
3. **Public struct literals.** `WindowOptions` and `WindowParams` gain `use_display_p3`; `WindowInsets` gains `corner_radii`. Use `..Default::default()` where the type supports it, or supply the new field explicitly.
4. **Custom Metal producers.** Replace direct `context.queue`/`context.objc2_queue()` recording with `context.record(|command| { /* encode and finish encoders */ Ok(()) })`. Use `MetalCustomContext::new` instead of a struct literal and `queue_identity()` for cache identity. Return pending commands to the host for submission. Resource handles remain objc2 types. `metal_renderer::new_renderer` gains a `use_display_p3` argument; the existing two-argument `MetalRenderer::new` is preserved.
5. **Sprite layouts.** Rust sprite field ordering and WGSL/HLSL layouts change together. Custom native integrations that mirror GPU layouts must review their offsets rather than relying on the previous layout.
6. **Property tests.** The wrapper now emits the Rust-path `proptest_path` syntax used by proptest 1.12. The old proptest Git override is removed. The async-process compatibility override remains for repository validation.
7. **Toolchain and features.** Edition 2024 is unchanged. Rust 1.99.0 is validated; no lower MSRV is newly promised. Hot reload is optional and debug-gated. Benchmark counters require `bench-support`; normal library defaults do not enable them.

## iOS publication proposal

The platform crate has a target-specific dependency on `xgpui-ios =1.26.2`. A registry release therefore needs that package available before publishing the platform, including when preparing archives on another host. This PR proposes crates.io permission for the first upstream-derived iOS package; actual publication still requires explicit approval. Its package version follows upstream while the iOS implementation remains unchanged; simulator/device runtime validation is documented separately.

## Validation and release gates

The integrated source passed Windows, Linux and macOS native builds, all platform benchmark targets and metrics/context tests, browser shaders, documentation/tooling checks, and iOS simulator compile/link/package checks. See the [integration CI run](https://github.com/gpui-luma-dev/xgpui/actions/runs/41634717655) and [tooling CI run](https://github.com/gpui-luma-dev/xgpui/actions/runs/41634713131). These runs precede the proposed manifest/version changes; the release PR validates the candidate again.

Preparation includes an isolated no-upload registry plan that checks every candidate archive and compares any existing version with its published payload. `xgpui-color` is intended to be verified and skipped. Registry-backed verification of crates depending on new versions must be repeated in dependency order as those versions become available; extracted-candidate checks do not establish registry availability.

Interactive iOS runtime testing, native graphical acceptance beyond the checks described, and final public API/version approval remain release considerations. After explicit merge approval, create the immutable source tag and reviewed draft release before any upload, then obtain publication and docs-deployment approval under [the release procedure](../RELEASE_PROCEDURE.md). No tag, upload, GitHub release record or deployment is performed by this preparation.
