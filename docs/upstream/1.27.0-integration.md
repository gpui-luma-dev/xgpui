# GPUI 1.27.0 integration and API review

Integrated on `codex/sync-gpui-1.27.0` from local commit `8ed97a3`, using upstream
`f98d4e26ca850515c1682ae4cd6e2b8277dae6e7`. Implementation is prepared for review;
public API approval remains pending; the selected crate versions and exact pins
are applied in this branch. No release or merge has been performed.

## Breaking changes to XGPUI API

This migration changes the API exposed by XGPUI's core and Apple backend crates.
Applications upgrading from the current XGPUI packages should review the changes
below even if they do not use an optional extension. The table distinguishes
upstream changes carried into XGPUI from adaptations to our GPUI interfaces.

| Origin | Breaking change in XGPUI | Application migration |
| --- | --- | --- |
| Upstream GPUI | Keystroke parsing, display, formatting and secondary modifiers use the runtime host OS. Static constructors require static strings; direct keystroke `Display` implementations are removed. | Use `KeyBinding::load` or `Keystroke::parse_with_os` for dynamic input; pass the host OS or App context when formatting and resolving modifiers. |
| Upstream GPUI | `Window::text_system()` returns an Rc handle; hash-based layout methods are removed. | Keep window text caches local to their window thread and use ordinary `shape_line` and `layout_line` calls. |
| Upstream GPUI | External `Platform` implementations must provide `platform_info`. | Return the host OS and native/web delivery target. |
| Upstream Apple changes adapted to XGPUI | Renderer constructors now return `Result`; our renderer factory drops its unused native window, view and bounds arguments. | Propagate initialization errors and remove the unused arguments. XGPUI retains its existing color-mode negotiation and typed resource interfaces. |
| Upstream Apple changes | The public `thermal` module is replaced by `process_info`; macOS 12.0 is the minimum. | Update observer imports and retain the returned observer owner; update deployment requirements. |

XGPUI's own GPUI changes provide the core integration points used by our font,
color, drawing, media and paragraph extensions. Those maintained differences,
including earlier breaking changes to font and style structs, are described in
[GPUI API changes](../extensions/gpui-public-api.md). The detailed review below
records each API change in this sync, its origin, compatibility impact and
application migration. Final API approval remains pending.

## Implementation

- Adopted typed upstream AppKit application, window, event, menu, keyboard,
  display, clipboard and appearance bindings; removed private `native_appkit`.
- Retained XGPUI Metal resources, custom draw, wide SDR, media surfaces, caches,
  headless capture, and validation interfaces. Ported fallible device, library,
  pipeline, buffer, command queue and CoreVideo-cache initialization. Adopted
  validated atlas uploads while preserving our scoped texture ownership wrapper
  and eviction/lifetime regression tests.
- Preserved local Services submenu registration, nullable pasteboard handling,
  Objective-C protocol/signature audits, optional text-range output handling,
  and attributed-string autorelease behavior. These fixes still apply to the
  upstream typed implementation.
- Adopted power/platform introspection, host-aware key semantics, macOS atomic
  credential insertion, deferred native-close handling, list scroll anchoring,
  subscription activation changes, fallback caching and OHOS target exclusion.
- Replaced window text locks with RefCell state and Rc ownership. Adapted our
  paragraph cache, retained-element reuse and generation invalidation; retained
  font axes/features/fallback controls and missing-glyph reporting.
- Fixed scramble typography to re-shape its source font request when CoreText
  returns a size-specific face absent from reverse lookup. Replacements still
  require an exact native face match, preserving fallback and emoji behavior.
- Supporting crates and provenance now reference 1.27.0. Existing XGPUI package
  versions follow the selected release table below. Final API review remains
  pending. macOS now
  requires 12.0; Metal shader compilation uses the same minimum.

## Concrete public API changes

Each row is an individual review item. Origin identifies upstream GPUI changes,
upstream Apple changes, and adaptations to XGPUI’s existing backend API.
No serialized struct shape changes were
identified. Keystroke serialization here means emitted keystroke strings; host
OS changes their modifier spelling and alias interpretation. Platform identity
and PowerMode types do not add serde implementations. Existing package exports,
including `ctor`, spring types, benchmark macros and typed Metal resource aliases,
are retained. `MetalRenderer::layer` already used our CAMetalLayer alias and has
no new source signature change.

| Implemented API change | Purpose and compatibility impact | Migration | Origin |
| --- | --- | --- | --- |
| `PlatformInfo { os, target }` | Add runtime host identity independent of delivery target; additive type and fields. | Read `App::platform_info()`. | Upstream GPUI |
| `OperatingSystem` | Add host OS enum, including unknown hosts. | Match with appropriate handling of all variants. | Upstream GPUI |
| `PlatformTarget` | Distinguish native and web delivery. | Avoid inferring host OS from build target. | Upstream GPUI |
| `PlatformInfo::is_mac` | Add convenience predicate. | Optional use. | Upstream GPUI |
| `Platform::platform_info` | Required trait method; breaks external platform implementers. | Implement host and delivery identity in every platform. | Upstream GPUI |
| `App::platform_info` | Expose platform identity to clients. | Replace compile-time assumptions where host semantics matter. | Upstream GPUI |
| `PowerMode` | Add Unknown, LowPower, Balanced, HighPower. | Handle Unknown; macOS reports LowPower or Unknown. | Upstream GPUI |
| `Platform::power_mode` | Defaulted trait method; additive. | Override when supported. | Upstream GPUI |
| `Platform::on_power_mode_change` | Defaulted callback registration; additive. | Notify through safe deferred delivery. | Upstream GPUI |

UTType changes, and private subscriber-set changes are not downstream public
APIs. Benchmark macros moved into a private module while retaining their exported
names and availability. The shared Apple source mirror repeats core changes and
is not a separate public API family.

## XGPUI backend adaptations

The renderer factory drops its unused native window, view and bounds arguments,
while `MetalRenderer::new` keeps XGPUI's existing two arguments and separate color
negotiation. Both adopt upstream's fallible initialization. These changes adapt
existing Apple backend entry points used to create platform windows; an extension
cannot change their signatures or initialization error handling.

XGPUI's existing font, color, drawing, media and paragraph integration points are
preserved. Their core-versus-extension design belongs in the maintained
[GPUI API changes](../extensions/gpui-public-api.md) guide. The upstream APIs in
this migration retain their upstream role and are reviewed for compatibility.
