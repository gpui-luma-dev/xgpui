# GPUI 1.29.3 upstream change accounting

For [issue #406](https://github.com/gpui-luma-dev/xgpui/issues/406): every upstream change in
scope is accounted for as adopted, adapted, already covered, or not adopted with a reason.
The source list is the 61 files that upstream changed between the pinned 1.28.1 and 1.29.3
snapshots in the [comparison](1.29.3-comparison.json). Paths are relative to `gpui/crates/`.
Commit-level context is in the [Zed release context](1.29.3-zed-context.md).

Conflict policy throughout: XGPUI's code wins. "Adapted" means upstream's change was ported
into XGPUI's version and keeps XGPUI's behavior on conflict. Several files carry changes for
more than one package; each package took only its own hunks.

Status as of November 21, 2026: packages 01–07 are merged into `issue-406/epic`; 08 is this
final review.

## Corrections made during the sync

- The investigation listed `TabStopMap::next`/`prev` as public API; `TabStopMap` is
  `pub(crate)` (corrected in 06).
- The investigation described an XGPUI COLR compositor; the GPU path and its test were
  upstream 1.28.1 code that XGPUI never modified (corrected in 05).
- `normalize --check` failed on `main` before the sync (stale `upstream.json` versions and a
  missing `xgpui-curve`), and the normalizer would have versioned the path-only
  `gpui-macros` → `gpui` dev edge (both fixed in 02).

## Known follow-ups

- `xgpui-windows` tests compile only with `--features test-support` (`PlatformHeadlessRenderer`
  gating); pre-existing.
- `hello_web` is still unbuildable (upstream directory names in its paths) and needs nightly;
  pre-existing.
- Visual checks after the epic reaches `main`: Windows color emoji (CPU compositing), Wayland
  frame pacing on a real compositor, Linux/Windows combining-mark placement.
- xgpui-luma removes its hand-written `IntoElement` impls after the release.
- The unmerged `issue-37/rounded-overflow` branch deletes `impl IntoElement for ClipElement`
  when it updates from `main`.

## Versions

Decided in the release issue, per the release process. Preview: `xgpui` takes a major bump
(4.2.0 → 5.0.0) for the compile-breaking changes listed on the
[migration page](../../pages/gpui-1.29-migration.html), and crates whose public API exposes
core types take a breaking bump under the type-identity rule used for 1.28.1.
