### Why 1.29.3

gpui-unofficial published 1.29.1, 1.29.2 and 1.29.3; there is no 1.29.0
release. Zed's range from the `v1.29.x` preview commit (`44372cd67`) to
`v1.29.3` touches no path in the capture's crate inventory. Every GPUI change
is in the 1.29.0 development range, so the three point releases are identical
for us apart from version numbers.

Zed's `v1.28.1` and `v1.29.3` are on diverged release branches: `v1.29.3` is
94 commits ahead and 8 behind (merge base `784374c6794a`). The 8 are the
`v1.28.x` preview/stable bumps and cherry-picks whose changes are also among
the 94: #66736, #66737, #66195 and #66732 as originals, #66841 as its own
`v1.29.x` cherry-pick. `xgpui-release context` used to reject this with "Zed
commits do not form forward range". It now accepts diverged release branches,
reports merge base → incoming as the range and lists the recorded release's own
commits separately, marking whether each cited PR is also in range. Here all
five cherry-picks are; only the pasteboard one (#66736) touches captured crates.

## Conflict policy

XGPUI's changes win. Where upstream and XGPUI both changed a file, port the
upstream change into our version and keep our behavior on any conflict. Never
replace or delete a downstream-edited file with upstream's copy. `review
code|cargo|metadata` enforces this. If an upstream change cannot coexist with
ours, record it as deferred with the reason.

## Public API impact

Core (`xgpui`) changes that need individual review:

- `Element` no longer has `IntoElement` as a supertrait; a blanket
  `impl<T: Element> IntoElement for T` replaces per-type impls. Any type with
  both `impl Element` and a hand-written `impl IntoElement` fails to compile.
  `AnyElement::new` (crate-private) becomes private; `Element::into_any`
  avoids double boxing.
- `GraphicalEnvironment` (Linux/FreeBSD) gains the public field
  `current_desktop`. The struct is not `#[non_exhaustive]`, so struct literals
  break. `desktop_environment()` is added on every platform.
- `Along::apply_along` takes `impl Fn` instead of `impl FnOnce`; `Edges<T>`
  implements `Along` and `Add`.
- `TabStopMap::next` / `prev` take `&mut self`; `TabStopOrderNodeSummary` and
  `TabStopCount` are removed.
- `TextSystem::layout_line` becomes generic over its text argument.

Hand-written `IntoElement` impls on element types (counted on `main` and
xgpui-luma `main`):

the xgpui release.

## Semantic review items

- **Windows COLR (05):** upstream removes the GPU color-glyph raster pass
  (`color_text_raster.hlsl`, its `build.rs` and renderer hooks) in favor of CPU
  compositing. XGPUI's `direct_write.rs` already has `composite_color_layers`
  and the `color_emoji_composites_over_cleared_texture` test. Compare output
  and decide; keep XGPUI's variable-font pass and zero-glyph early return.
- **Text system (04):** check upstream's shaped-line and shared-text changes
  against `paragraph_cache.rs`, `paragraph_fallback.rs`,
  `text_layout_provider.rs` and font variations, and against #325 part C.
- **Wayland (07):** upstream removes 74 lines from `client.rs` for frame
  timing; keep #271 diagnostics and #119 recovery.
