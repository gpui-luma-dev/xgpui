# GPUI 1.30.2 change accounting

Package 01 of [issue #458](https://github.com/gpui-luma-dev/xgpui/issues/458). This is the proposed ownership and disposition of the incoming changes. Update this ledger as package PRs land. The [comparison](1.30.2-comparison.json) also records local-only files, which are retained by default.

## Package assignments

- **02 · dependencies-svg** reviews all eight changed manifests and the 17 helper pins. Coordinate renderer-only manifest hunks with packages 04 and 05. Port the SVG filter/dependency work here and the SVG text API with 06.
- **03 · input-platform** takes keymap and Web fixes, then adapts platform input, test hooks, notification, window, diagnostic, and text changes around local behavior.
- **04 · scene-depth** ports ordering, batching, depth, clipping, shadows, outlines, and host/shader changes. Includes the coherent Apple cbindgen input update, with path and animation hunks picked up by 05 and 06.
- **05 · path-rendering** ports tiled paths behind the current path and brush APIs. Retains legacy backend path exports pending API review.
- **06 · retained-svg-animation** adapts scene animation and timing, benchmark/example changes, and the SVG text API. Keep the executor clock and capture semantics.
- **07 · api-review** reviews the API ledger against the implemented diff.
- **08 · integration-accounting** advances provenance after acceptance, records deferred changes, and retains downstream package READMEs. The ten incoming README changes carry regenerated upstream documentation. Review useful documentation hunks before adopting any.

## Registry helpers

All 17 helper identities are retained. Package 02 advances the helper policy to 1.30.2 and resolves the 14 helpers used by the root workspace at that version. Only `path`, `util`, and `zlog` have Rust source changes in the published snapshots. Those three are outside the root lockfile.

Package 02 also adopts resvg/usvg 0.49 internally with SVGZ support and preserves the public usvg 0.46 error type. The existing SVG lab checks both the downstream type and the displacement-map regression. The captured source ref stays at 1.29.3 until the final integration. Renderer-specific dependency changes remain assigned to their corresponding packages.

Package 02 synchronizes the stale distribution versions in `upstream.json` with the existing release map and crate manifests. This changes recorded metadata only. The dependency graph check passes, and normalization produces no changes when given the committed LF inputs.

## Package 03 input and platform

- Adopt the upstream keymap filter reorder, Web symbol-Shift normalization and safe-area styling through CSSOM.
- Add headless scale-factor simulation using the existing test-window machinery. Keep the existing `TestAppContext` API.
- Adapt the Win32 display-change deferral using a weak window reference. Extend the registered Windows input probe to send `WM_DISPLAYCHANGE` during a GPUI window update.
- Adapt the macOS notification worker while keeping `App::dismiss_system_notification` and the platform trait method's existing unit return. The worker queues posts and dismissals in order. Keep the upstream worker ordering test.
- Adapt default window placement to the active display and the latest cached bounds, including during a window update. Keep the existing `WindowBounds::centered` signature and explicit placement options. Adopt the Linux notifications for same-size maximize and fullscreen transitions. On Wayland, a resize that already notified observers covers the fullscreen transition without a second callback.
- Adopt the macOS native titlebar toggle and restore titlebar state after failed fullscreen transitions. Adopt the decoration simulator and same-size fullscreen notification in the test platform. Keep downstream shell policy and caption handling.
- Adapt app, display, window, and macOS frame-source diagnostics. Keep GPU information available through the existing platform query. Omit the upstream Metal renderer and display-link getters and the cursor reverse lookup, which would expand the renderer and cursor API surface.
- Adopt the font fallback cache's redundant-clone removal. The profiler atomic rename is already present locally. Leave formatting-only X11 clipboard changes out. The layer-batching changes in text painting belong to package 04.

## Package 04 scene sorting and readback

- Port the upstream compact-key sort for quads, shadows, underlines and atlas sprites. Keep the same sort keys and insertion order for ties. Continue sorting the existing path, backdrop, custom draw, shader and layer-boundary records with their current keys.
- The paint lab compares the blurred prefix with and without a later opaque quad that overlaps the sampling halo. It checks the final foreground pixel, retained replay output and backdrop cache keys. A deliberately reordered scene checks that the fixture detects contamination.
- Adapt batching by finding the first two ordered primitive kinds without sorting the full set. Keep the existing kind precedence, batch boundaries, shader mask grouping, and retained paint operations. Keep the public bounded layer APIs.
- Adapt overdraw reduction to a depth-enabled, front-to-back pass for one contiguous run of overlapping, opaque, borderless rectangular quads. Run it at that batch's original position on Metal, D3D11 and storage-buffer wgpu. Retained capture groups, wide native compositor paths and WebGL2 use the existing draw path. Translucent and rounded primitives stay in painter order. The broader upstream frame-wide depth split is deferred because it would cross local pass boundaries.
- Port vertex clipping for stock quads, shadows, underlines and polychrome sprites, plus video surfaces where the upstream backend supports them. Keep existing transform and path-mask clipping for other draws.
- Port the outline coverage compositing and zero-alpha guard. Use Levien's shadow approximation while retaining the separate inset hole and element clip in our existing shadow record. Retain the public scene and GPU instance layouts used by extension producers.

## Package 05 tiled paths

- Carry analytic outlines alongside the existing Lyon triangles. Bin eligible stock fills and strokes in device pixels and submit tiles in the existing scene batch order on D3D11, Metal, and storage-buffer wgpu. Retained scene replay keeps the same tile data and command identity. Clip tile bounds to the content mask and account for the antialiasing margin when ordering scene primitives.
- Keep legacy coverage for paths with edited public vertices or bounds, manually constructed triangles, asymmetric caps and variable-width strokes, and on the WebGL2 and Metal wide-color compositor routes. Shader brush masks and direct brushes continue to consume the same triangle stream.
- Check stock fills, curved strokes, edited vertices, shader brush masks, and direct brush pixels at 1× and 1.5× in the paint lab. Compare each screenshot with a retained replay. The epic workflow runs these checks on Linux, Windows, and macOS.
