# GPUI 1.29.3 public API ledger

Running ledger for [issue #406](https://github.com/gpui-luma-dev/xgpui/issues/406).
Each work package adds the public API changes it introduces to non-extension
crates, including re-exports and changes reached through re-exported helper
crates. Every entry needs the user's individual review before release. Approving
the implementation does not approve the API.

Review outcome is one of: pending, approved, changed, rejected.

## 02 — Dependencies

Helper crates move from 1.28.1 to 1.29.3. Only two changed code:
`gpui-shared-string` (below) and `util`, which adds `parse_path_with_position`.
`util` is not in XGPUI's dependency graph. No helper adds, removes or renames a
public item that `xgpui` re-exports.

### `gpui::SharedString` equality and hashing are hand-written

- **Change:** `xgpui` re-exports the helper crate (`pub use gpui_shared_string::*;`
  in `gpui.rs`). In 1.29.3 `SharedString` no longer derives `PartialEq` and `Hash`;
  it implements them by hand. `PartialEq` first compares pointer and length, then
  falls back to comparing contents. `Hash` hashes the contents as before.
- **Origin:** [zed#66728](https://github.com/zed-industries/zed/pull/66728), avoid
  comparing the bytes of shared text.
- **Source compatibility:** the trait set and results are unchanged. One edge case
  breaks: a derived `PartialEq` made `SharedString` usable as a constant in `match`
  patterns (structural equality), and a hand-written one does not. So
  `const X: SharedString = SharedString::new_static("..");` can no longer appear as
  a pattern. XGPUI's two such constants (`styled.rs`, Wayland `client.rs`) are not
  used as patterns; xgpui-luma has none.
- **Serialization/string formats:** none. Hash values are unchanged.
- **Migration:** compare with `==` or match on `.as_ref()` with string literals.
- **Could live in an extension:** not applicable. This is a pinned helper crate.
- **Versioning:** source-breaking only in the pattern edge case; counts toward the
  `xgpui` version proposal in package 08, which is already a major bump for 03.
- **Review outcome:** pending.

## 03 — Element and IntoElement

### Blanket `IntoElement` for every `Element`; `Element` drops its `IntoElement` supertrait

- **Change:** `pub trait Element: 'static + IntoElement` becomes `'static + Sized`, and
  `impl<T: Element> IntoElement for T` (with `Element = Self`) replaces each element's
  hand-written impl. `Element::into_any` is overridden for `AnyElement` so converting an
  `AnyElement` no longer boxes it again; `AnyElement`'s constructor stays private.
- **Origin:** [zed#64864](https://github.com/zed-industries/zed/pull/64864).
- **Source compatibility:** breaking for any downstream type that implements both
  `Element` and `IntoElement`: coherence rejects the overlap (E0119). Unaffected:
  `IntoElement` on types that are not `Element`s (components, `#[derive(IntoElement)]`),
  and code bounded by `E: Element` or `T: IntoElement`. XGPUI removes 28 such impls in
  core and 6 in extensions (shader 3, media 2, parley 1); xgpui-luma has at least 5.
- **Serialization/string formats:** none.
- **Migration:** delete the `impl IntoElement for YourElement` block.
- **Could live in an extension:** no. Trait coherence is decided where the traits live.
- **Versioning:** breaking; `xgpui` major bump, and dependents exposing element types
  follow the type-identity rule in package 08.
- **Review outcome:** pending.

`Div`'s `Interactivity` moving out of line ([zed#66719](https://github.com/zed-industries/zed/pull/66719))
changes only a private field; `Interactivity` keeps `new()` and `Default`. No public API
change.

## 06 — Core elements

### `Along::apply_along` takes `impl Fn`

- **Change:** `fn apply_along(&self, axis: Axis, f: impl FnOnce(Self::Unit) -> Self::Unit) -> Self`
  becomes `impl Fn(..)`, on the trait and on the `Point` and `Size` impls.
- **Origin:** [zed#66614](https://github.com/zed-industries/zed/pull/66614); `Edges` applies
  `f` to two sides, so it must be callable more than once.
- **Source compatibility:** breaking for external `Along` implementors (signature
  mismatch) and for callers passing a closure that can run only once. Neither xgpui
  nor xgpui-luma does either.
- **Serialization/string formats:** none.
- **Migration:** implementors change `FnOnce` to `Fn`; callers clone captured values
  instead of moving them out.
- **Could live in an extension:** no; it is a core trait.
- **Versioning:** breaking; covered by the `xgpui` major bump.
- **Review outcome:** pending.

### `Edges<T>` implements `Add` and `Along`

- **Change:** `impl Add for Edges<T>` (per side) and `impl Along for Edges<T>`
  (`along` sums the two sides on an axis; `apply_along` maps both). `Mul for Edges`
  drops redundant clones without changing its bounds.
- **Origin:** [zed#64056](https://github.com/zed-industries/zed/pull/64056) and
  [zed#66614](https://github.com/zed-industries/zed/pull/66614), used for `list()`
  padding.
- **Source compatibility:** additive. Code that implemented `Add` or `Along` for
  `Edges` itself cannot exist outside core (orphan rule).
- **Serialization/string formats:** none.
- **Migration:** none.
- **Could live in an extension:** no; trait impls on a core type.
- **Versioning:** minor on its own.
- **Review outcome:** pending.

### `randomized_element_tree` gains `ChildText` and `with_paths` (`bench-support` only)

- **Change:** `RandomizedElementTreeMutationKind` and `RandomizedElementTreeMutation`
  gain a `ChildText` variant (`ALL` grows from 16 to 17 entries), and
  `RandomizedElementTreeConfig::with_paths` is added.
- **Origin:** upstream benchmark work for the text-system changes.
- **Source compatibility:** breaking only for exhaustive matches by users of the
  `bench-support` feature.
- **Serialization/string formats:** none.
- **Migration:** add a `ChildText` arm.
- **Could live in an extension:** it is test/bench support behind a feature already.
- **Versioning:** covered by the `xgpui` major bump.
- **Review outcome:** pending.

Behavior without API changes: `list()` lays out inside horizontal padding and
borders ([zed#64056](https://github.com/zed-industries/zed/pull/64056)); a drag's cursor
applies before the next paint and the cursor is resolved after listeners on every mouse
event ([zed#66540](https://github.com/zed-industries/zed/pull/66540)); animated WebP decodes
all frames in `Image::to_image_data` ([zed#66459](https://github.com/zed-industries/zed/pull/66459)),
and GIF/WebP decode errors no longer name the image source.
